# Screen contracts

Ces contrats détaillent seulement les écrans de référence qui fixent le langage de l'application.
Ils restent **Draft** jusqu'à validation d'une capture sur petit Android et iPhone standard.

1. `client-discovery.md` — recherche, voix, filtres et résultats.
2. `broker-detail.md` — confiance, biens et contact persistant.
3. `property-editor.md` — publication guidée d'un bien.

`../UX-FLOWS.md` reste le registre complet de tous les écrans. On crée un nouveau contrat séparé
uniquement lorsqu'un écran devient une référence réutilisée ou qu'il porte assez d'états pour que
le tableau de `../UX-FLOWS.md` ne suffise plus.

Pour approuver un contrat : joindre les captures clair/sombre, texte ×1.3, état peuplé et
état vide/erreur pertinent ; exécuter les retours définis dans `../INTERACTION-FEEDBACK.md` sur un
appareil réel ; noter la date et remplacer `Draft` par `Approved`.
